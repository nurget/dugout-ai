# DUGOUT AI에서 RAG를 쓰는 이유

RAG는 Retrieval-Augmented Generation의 약자이며, 답변을 만들기 직전에 관련 문서를 찾아 그 일부를 모델 입력에 보태는 방식입니다. 모델을 새로 학습시키지 않고도 규정·전술 가이드처럼 자주 바뀌거나 출처를 확인해야 하는 지식을 답변에 연결할 수 있습니다.

## 요청 처리 흐름

1. 사용자가 질문합니다.
2. Agent가 야구 기록 질문인지 공개 문서 질문인지 판단합니다.
3. 공개 문서 질문이면 공개로 표시된 문서만 검색하고, 상위 문서 조각을 답변 입력에 넣습니다.
4. 모델은 검색 결과를 근거로 답하고, 검색 문서의 제목과 출처 URL을 함께 제시합니다.
5. 근거가 없거나 오래된 문서만 있으면 단정하지 않고 확인이 필요하다고 답합니다.

선수 성적과 경기 데이터는 구조화된 DB Tool로 조회합니다. RAG는 표의 수치를 다시 찾아오는 용도가 아니며, 문서에 없는 실시간 엔트리나 선수 컨디션을 알아내지도 않습니다.

## 비용과 지연

검색된 문서 본문은 모델 입력에 추가되므로 검색 결과가 길수록 입력 토큰과 응답 지연이 늘어납니다. 이 구현은 문서 검색 Tool 정의를 모든 질문에 보내지 않고 문서 질문으로 분류된 경우에만 전달하며, 검색 결과는 최대 3개로 제한합니다. 실제 증가 비용은 호출별 입력·캐시 입력 토큰과 모델 단가를 기록한 trace로 계산해야 합니다. 현재 운영 코퍼스가 없어 비용·정확도에 대한 실측값은 없습니다.

검색 결과 수를 줄이면 토큰 비용은 줄지만 필요한 근거를 놓칠 수 있습니다. 따라서 설정은 고정된 감으로 정하지 않고 다음 지표를 함께 보고 조정합니다.

- **Recall@k**: 정답 근거 문서가 상위 k개 검색 결과에 들어오는 비율
- **근거 일치율**: 답변의 주요 주장이 검색 문서로 뒷받침되는 비율
- **출처 정확성**: 제시한 제목·URL이 실제 검색 문서와 일치하는 비율
- **보류 품질**: 근거가 없거나 최신성이 불명확할 때 단정 답변을 피하는 비율
- **호출당 토큰과 지연**: RAG 미사용 질문과 사용 질문을 나누어 비교

자동 평가는 출처 메타데이터, 노출 범위, 결과 수, 필수 근거를 확인합니다. 근거와 답변의 의미상 일치는 사람이 검토해야 합니다. 현재 synthetic 사례는 기능 계약만 확인하며 실제 코퍼스의 정확도 평가로 간주하지 않습니다.

## 문서 권리와 접근 범위

문서는 수집 전에 공개·상업적 이용과 재배포 권한을 확인해야 합니다. 파일별 HTTPS 출처, 효력일, 라이선스 근거와 SHA-256을 manifest에 기록합니다. Vector Store에 올릴 파일은 `visibility=public` 속성으로만 공개 검색에 넣습니다. 구단 내부 문서는 이 저장소에 넣지 않으며, 테넌트별 저장소와 서버 측 권한 검사를 갖춘 뒤 별도 기능으로 설계해야 합니다.

KBO 웹사이트는 공식 API 또는 사전 서면 동의 없는 자동 수집을 제한합니다. 따라서 공식적으로 허가된 API나 이용 승인을 확보하기 전까지 KBO 웹페이지를 긁어 문서 코퍼스 또는 실시간 엔트리 피드로 사용하지 않습니다. 공식 페이지에서 확인할 수 있는 선수 등록 상태는 경기 당일 선발 라인업, 출전 가능 여부, 부상 및 컨디션과도 구분해야 합니다.

## 면접에서 설명하기

> DUGOUT AI는 기록 수치와 문서 지식을 분리합니다. 선수·경기 수치는 기준일 누출을 막기 위해 DB Tool로 조회하고, 규정·전술 문서 질문만 공개 문서 검색으로 보강합니다. 검색 문서를 제한된 개수로 답변에 넣고 출처를 표시하며, 문서가 없거나 최신성이 확인되지 않으면 보류합니다. 검색 본문이 입력 토큰 비용을 높일 수 있어 호출별 token usage를 기록하고, 검색 재현율·근거 일치율·비용을 함께 평가합니다.
